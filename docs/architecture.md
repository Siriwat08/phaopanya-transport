# สถาปัตยกรรมแอป AppSheet — เผ่าปัญญา ทรานสปอร์ต

> เอกสารนี้อธิบายภาพรวมสถาปัตยกรรมของแอปเพื่อให้ทีมใหม่เข้าใจระบบได้รวดเร็ว

## 🎯 วัตถุประสงค์ของแอป

แอปนี้ใช้บริหารงานขนส่งสินค้าของบริษัท เผ่าปัญญา ทรานสปอร์ต
ครอบคลุมทั้ง cycle ตั้งแต่รับงาน → ส่งสินค้า → วางบิล → อนุมัติ → เบิกส่วนต่าง → รับเอกสารคืน

## 📊 ตัวเลขสำคัญ

| รายการ | จำนวน | หมายเหตุ |
|---|---|---|
| Tables | 90 | แบ่งเป็น User (29) + Process (30) + Output (30) + System (1) |
| Columns | 2,254 | รวมทุกตาราง |

| Process Tables | 30 | AppSheet Automation bots |

## 🏗️ การจำแนกตาราง

### 1. User Tables (29 ตาราง)
ตารางที่ผู้ใช้สัมผัสโดยตรง แบ่งเป็นกลุ่ม:

- **งานหลัก**: `หน้าหลัก`, `ตารางงานประจำวัน`, `SCGนครหลวงJWDภูมิภาค`
- **การเงิน/วางบิล**: `ข้อมูลการวางบิล`, `ปริ๊นใบวางบิล`, `สรุปเบิกส่วนต่าง`
- **ตั้งราคา**: `Price_Table`, `PriceOverride`, `ราคาในระบบก่อนส่งสินค้า`, `ราคาน้ำมันดีเซล`
- **เอกสารส่งคืน**: `Doc_Return`, `Image_Doc_Return`, `ScanDocs`
- **งานส่งคืน**: `รับงานคืนได้เงิน200`, `ข้อมูลงานRT`, `ข้อมูลงานRW`
- **HR/รถ**: `ข้อมูลพนักงาน`, `ข้อมูลการเข้าบำรุงรักษา`
- **ระบบสนับสนุน**: `Announcements`, `Acknowledge_Logs`, `FILTER`, `แจ้งปัญหาระหว่างวัน`

### 2. Process Tables (30 ตาราง)
ตาราง state ของ AppSheet Automation bot  ตัวอย่าง:
- `Process for ปริ๊นใบวางบิล` + 13 ตัวแปรย่อย (แยกตามลูกค้า)
- `Process for Telegram_แจ้งปัญหา` — ส่งแจ้งเตือนเข้า Telegram
- `Process for ฺBot_4ตัว_จัดเรียงเส้นทาง` + `GoogleMapsRoutesAPI_Step`
- `Process for Bot_เบิกค่าขนส่งตามระยะทาง`

### 3. Output Tables (30 ตาราง)
ตารางผลลัพธ์ของแต่ละ step ใน process  ส่วนใหญ่เป็น `Clear Output`, `New step Output`

### 4. System Tables (1 ตาราง)
`_Per User Settings` — ตารางระบบของ AppSheet เก็บค่าตั้งค่ิอของผู้ใช้

## 🔐 ระบบสิทธิ์ผู้ใช้

ทุกตารางใช้ฟอร์มูลา `SWITCH(USERROLE(), ...)`:

| ตาราง | ADMIN | USER | READ_ONLY |
|---|---|---|---|
| ตารางงานประจำวัน, ข้อมูลการวางบิล, SCG นครหลวง | ALL_CHANGES | ADDS_AND_UPDATES | READ_ONLY |
| Price_Table, ราคาน้ำมันดีเซล, ข้อมูลพนักงาน | ALL_CHANGES | READ_ONLY | READ_ONLY |
| ทำเบิกส่วนต่าง SCG วังน้อย, Acknowledge_Logs | ALL_CHANGES | **ADDS_ONLY** | READ_ONLY |

## 🌐 การเชื่อมต่อภายนอก

1. **Google Sheets** — แหล่งข้อมูลหลัก
2. **Google Tables (AppSheet Database)** — สำหรับ `ข้อมูลพนักงาน`, `ข้อมูลชื่องานต้นทางปลายทาง`
3. **Google Maps Routes API** — คำนวณเส้นทางและระยะทาง
4. **Telegram Bot** — ส่งการแจ้งเตือนปัญหา
5. **Cross-App Navigation** — link ไปยังแอปอื่นสำหรับอัปโหลดรูปบิล
6. **Email** — ส่งเมลถึงพนักงานและผู้อนุมัติ

## 🛡️ ระบบตรวจจับทุจริต

ตาราง `SCGนครหลวงJWDภูมิภาค` มีฟิลด์ audit ที่ค่อนข้างแข็งแรง:

- `จุดส่งสินค้าปลายทาง` (LatLong) — ดึง `HERE()` อัตโนมัติ พร้อม validation GPS
- `พิกัดตอนกดบันทึกงาน` + `พิกัดตอนกดบันทึก_เปลี่ยนแล้ว` — เช็คว่าพิกัดเปลี่ยนหรือไม่
- `เวลาเริ่มกรอกงาน` vs `เวลาบันทึกงานสำเร็จ` — ระยะเวลาที่ใช้
- `ระยะขยับจากจุดเริ่มต้น_เมตร` + `ความเร็วการเคลื่อนที่_เมตร_นาที`
- `เวลาถ่ายรูปหน้าร้าน_หน้าบ้าน` — timestamp ถ่ายรูป
- `ผลการตรวจสอบงานส่ง` + `เหตุผิดปกติที่ตรวจพบ` — สรุปผลตรวจ

## 💰 ระบบตรวจสอบราคา

Format Rules ที่เกี่ยวข้อง:
- `แจ้งเตือนราคาหลังวิ่งงาน` — แดง เมื่อราคาในระบบ ≠ ราคาจริง (สำหรับ 9 ประเภทงาน)
- `แจ้งเตือนเช็คราคาแล้วปกติ` — เขียว เมื่อราคาตรง
- `อนุมัติ` / `รอการอนุมัติ` — เขียว/ส้ม บน `ข้อมูลการวางบิล`
- `Green_Done` — เขียว เมื่อ `ScanStatus = "สแกนแล้ว"`
- `ทำเบิกได้` / `ทำเบิกไม่ได้` — เขียว/แดงขีดฆ่า ตามค่าส่วนเพิ่ม

## 🔄 Approval Workflow

`ข้อมูลการวางบิล` มีคอลัมน์ `สถานะการอนุมัติ`:
- `"รอการอนุมัติ"` → `"อนุมัติ"` (เฉพาะ ADMIN)
- Action "อนุมัติ" และ "รอการอนุมัติ" ทำงานเฉพาะเมื่อ `USERROLE() = "ADMIN"`

## ⚠️ ปัญหาที่ทราบแล้ว

1. `Deployable? = No` — แอปยังไม่สามารถ deploy ได้ ต้องตรวจสอบสาเหตุ
2. Source Path ไม่เอากัน — บางตารางใช้ `google` source, บางตารางใช้ `google_tables`
3. Hard-coded ชื่องาน 9 ชื่อใน Format Rule
4. Process Table ซ้ำซ้อน — มี 14+ Process ของ "ปริ๊นใบวางบิล" แยกตามลูกค้า
5. ชื่อตารางอ้างถึงบุคคล เช่น `Process for ปริ๊นใบวางบิล_รับเอกสาร (งานพี่เหน่ง)`
